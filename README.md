# Mos-TRANS

Диспетчерская наземного транспорта с тремя сервисами: **frontend** (React/MapLibre), **backend** (FastAPI и TCP-приёмник NDTP), **ml** (FastAPI и CatBoost). В дашборде отдельные вкладки **NDTP** для живого потока и **История** для воспроизведения датасета с прогнозами.

- [Инструкция для жюри](https://мостранс.хелпи.рф/instructions) — команды подачи потока, проверка, прогнозы и метрики.
- [Живой дашборд NDTP](https://мостранс.хелпи.рф/) и [исторический срез с прогнозами](https://мостранс.хелпи.рф/?mode=history&at=50000)
- [Документация проекта](https://мостранс.хелпи.рф/docs) и [Swagger API](https://мостранс.хелпи.рф/api)
- [Проверка требований и ограничений](REQUIREMENTS.md)

## Запуск трёх модулей в Docker

1. Скачайте [архив датасета организаторов](https://disk.yandex.ru/d/CA6tsj4aJJ4Aaw) и сохраните как `data/dataset.zip`. Архив не включён в Git.
2. Из корня репозитория запустите:

```sh
docker compose up -d --build
```

3. Дождитесь `"status":"ready"` от `http://localhost:8000/api/health`. Первый запуск готовит признаки из датасета и может занять несколько минут.
4. Откройте дашборд `http://localhost:8080`, Swagger `http://localhost:8000/api`. TCP-приёмник NDTP слушает `localhost:9201`.

Для развёрнутого сервера используются `compose.server.yaml` и [описание сервера](deploy/SERVER.md). Этот Compose-файл использует существующую Caddy-сеть сервера; для чистого локального запуска используйте обычный `docker-compose.yml`.

## Подача NDTP

Сервер принимает бинарные кадры эмулятора: handshake `NPH_SGC_CONN_REQUEST`, затем `NPH_SND_REALTIME` с `G6CellNav00`. CRC проверяется. `peerAddress`/`unitId` сопоставляется с `unit_id` в `validate/traffic.csv`, затем с `tr_id` и остановками `validate/schedule_plan.csv`.

Для внешнего подключения используйте ASCII-имя домена **`xn--80axeckfde.xn--e1agiq1a.xn--p1ai`** и TCP-порт **9201**. В настройке `targetHost` эмулятора передаётся только имя, без `https://`. Готовый JSON-конфиг и команды Docker находятся в [инструкции для жюри](https://мостранс.хелпи.рф/instructions). Официальный образ эмулятора лежит внутри архива датасета как `ndtp-telemetry-emulator.tar`.

Чтобы отправить реальные строки датасета в том же NDTP-формате:

```sh
python scripts/send_ndtp_sample.py --dataset data/dataset.zip --host xn--80axeckfde.xn--e1agiq1a.xn--p1ai --port 9201 --vehicle 131672 --count 3
```

Проверка: `GET /api/health` увеличивает `ndtpFrames` без роста `ndtpErrors`; `GET /api/live/snapshot` возвращает ТС `131672`, терминал `985940`, координаты и остановку. В дашборде отображаются пакеты, полученные за последние 120 секунд. Для архивных NDTP-пакетов свежесть считается от получения, а исходное время пакета сохраняется в `gpsEventTime`.

**Ограничение:** новые NDTP-пакеты сейчас привязываются к маршруту и отображаются, но прогноз задержки по ним не рассчитывается.

## Прогнозы и метрики

Исторический API строит прогнозы на 6 января 2026 года: `GET /api/replay/snapshot?at=50000`, где `at` — число секунд от полуночи. Вкладка **История** показывает эти срезы на карте: можно выбрать время, запустить воспроизведение, изменить скорость, открыть карточку ТС, прогноз, объяснение и события. Для каждого ТС с готовым прогнозом `estimateSeconds` — ожидаемая задержка, `probability` — вероятность задержки более 120 секунд, `reason` и `recommendation` — объяснение и действие. Пороги индикации: до 70% низкий риск, 70–89% средний, от 90% высокий. Это экранные уровни риска; автоматической рассылки алертов нет.

Модель использует только пакеты с `event_time ≤ T` и `receive_time ≤ T`; фактическое прибытие к целевой остановке не подаётся модели как признак. Метрики опубликованного датасета:

| Оценка | Результат | Источник |
| --- | ---: | --- |
| MAE задержки на размеченном test, 353 точки | 55,90 с | [Регрессия](artifacts/route_delay_trend_submission/metrics.json) |
| Brier score вероятности задержки >120 с, групповой holdout | 0,1334 | [Вероятность](artifacts/calibrated_probability/metrics.json) |

Эти оценки не измеряют качество на новом дне или живом потоке. Для Data Science готов `artifacts/integrated_submission/submission.csv` с 151 строкой validate. Датасет в Git отсутствует; для повторного расчёта он нужен локально.
