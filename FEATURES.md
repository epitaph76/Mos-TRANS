# Контракт общей предобработки v1

Это выход **общего ядра** предобработки, используемый действующими моделями CatBoost. Источник — `data/dataset.zip` или распакованная папка с теми же CSV. Данные не добавляются в Git. Действующая модель также использует производные маршрутные и исторические признаки из `mos_trans.features`; они описаны ниже.

## Выходы

| Файл в `data/processed/` | Содержимое |
|---|---|
| `traffic_clean.parquet` | Единый очищенный пул телеметрии, одна строка на `packet_id` |
| `{train,test,validate}_samples.parquet` | Точки прогноза и target, без признаков |
| `{train,test,validate}_features.parquet` | Одна строка на `sample_id`, общие признаки и target |

Строки упорядочены по `sample_id`. ID хранятся как строки. Время — наивные timestamp в единой шкале исходных CSV; преобразования часового пояса нет. `target_delay_s` и `target_delta_s` в validate равны `null`. Для train/test `target_delta_s = target_delay_s - cur_dev_s`; после прогноза `prediction = cur_dev_s + predicted_delta_s`. `target_delay_s` и `target_delta_s` запрещено подавать модели как признаки. `sample_id`, `T` и `target_time_begin` также служат метаданными, а не готовыми числовыми входами.

## Доступность и очистка

- Для точки `(sample_id, T)` доступен только пакет с `event_time <= T` **и** `receive_time <= T`. `available_time` в очищенном файле — максимум этих двух времён; при отсутствии `receive_time` пакет не используется в признаках.
- Дубликаты `packet_id` объединяются в один пакет; при несовпадении содержимого ядро останавливается с ошибкой. В очищенном файле остаются все времена, включая будущие относительно отдельных точек. Любой последующий расчёт признаков обязан повторно проверять доступность пакетов на своё время `T`.
- Скорость вне `[0, 100]` км/ч становится `null`; `speed_outlier=true`. Невалидный GPS (`location_valid=false`, пустые или невозможные координаты) превращается в `lon=null`, `lat=null`, `gps_valid=false`. Допустимая скорость из такого пакета сохраняется.
- Последняя координата своего ТС действительна не дольше 120 секунд. Последняя скорость действительна не дольше 120 секунд. Для соседнего ТС координата действительна не дольше 60 секунд. Возраст считается по `event_time`.
- Расписание берётся **только из соответствующего split**: `train/schedule.csv`, `test/schedule.csv`, `validate/schedule_plan.csv`. Поле `time_fact_begin` вообще не читается. Разметка используется только для target train/test; статистики по прошлым target не рассчитываются.

## Поля таблицы признаков

| Поле | Определение |
|---|---|
| `sample_id`, `tr_id`, `T`, `target_stop_id`, `target_time_begin` | Ключи и времена точки прогноза; ID строковые |
| `cur_dev_s` | Известное на `T` отклонение, секунды |
| `target_delay_s`, `target_delta_s` | Цели только для train/test, секунды; не входы модели |
| `realtime_data_age_s` | Возраст последнего доступного пакета своего ТС, секунды; `null`, если пакетов нет |
| `realtime_speed_last`, `realtime_speed_age_s` | Последняя допустимая скорость и её возраст, до 120 секунд |
| `realtime_gps_age_s`, `realtime_distance_to_target_m` | Возраст последнего валидного GPS до 120 секунд и расстояние по сфере до целевой остановки, метры |
| `realtime_packet_count_{2,5,10}m` | Число доступных пакетов в закрытом окне `[T − окно, T]` |
| `realtime_speed_count_{2,5,10}m` | Число пакетов с допустимой скоростью в том же окне |
| `realtime_speed_mean_{2,5,10}m`, `realtime_speed_std_{2,5,10}m` | Среднее и стандартное отклонение скоростей (по пакетам, population std), км/ч; `null` без скорости |
| `realtime_stopped_fraction_{2,5,10}m` | Доля пакетов с допустимой скоростью `<= 2` км/ч; `null` без скорости |
| `context_vehicle_count_500m` | Число **других** ТС в 500 м от последнего валидного GPS своего ТС; одно последнее валидное положение на соседнее ТС, возраст до 60 секунд |
| `context_speed_count_500m` | Число таких соседей с допустимой скоростью в выбранном GPS-пакете |
| `context_speed_mean_500m`, `context_speed_median_500m` | Средняя и медианная скорость этих соседей, км/ч; `null` при отсутствии скоростей |
| `context_stopped_fraction_500m` | Доля таких соседей со скоростью `<= 2` км/ч; `null` при отсутствии скоростей |
| `schedule_horizon_s` | Время от `T` до планового прибытия к целевой остановке, секунды; должно быть `(600, 900]` |
| `schedule_target_lon`, `schedule_target_lat`, `schedule_target_address` | Координаты и адрес целевой остановки из планового расписания split |
| `schedule_stops_remaining` | Число плановых записей этого ТС с временем `(T, target_time_begin]`, включая целевую; записи с одинаковым временем считаются отдельно |
| `historical_hour`, `historical_day_of_week` | Час `T` (0–23), день недели `T` (понедельник = 0) |
| `historical_time_sin`, `historical_time_cos` | Циклическое время суток в точке `T` |

Если собственный GPS отсутствует, контекстные счётчики равны нулю, а контекстные скорости — `null`. Это отличается от наличия GPS и нуля соседей через `realtime_gps_age_s`. Числовые пропуски не заполняются нулём.

## Производные признаки действующей модели

`python -m mos_trans.features.build` дополняет общие таблицы и пишет `data/processed_route/{train,test,validate}_features.parquet`. `route_signature`, `section_id`, плановые координаты границ участка, его длительность и доля планового прохождения берутся только из плановой части расписания. `previous_cur_dev_s`, `cur_dev_lag_2`, возраст предыдущих точек и темп изменения отклонения считаются по более ранним точкам **того же ТС**. Для основных таблиц это история опубликованных точек прогноза, а не непрерывная история всех пакетов. Для потоковых точек эти признаки строятся из последовательности полученных пакетов, поэтому распределение входов может отличаться от обучающего.

`mos_trans.stream_forecast` заранее строит `data/processed_route/stream/stream_features.parquet` и `stream_status.parquet` из исторического архива. В потоковой таблице `T = max(event_time, receive_time)` текущего пакета, `cur_dev_s` оценивается по GPS и плановому маршруту; опубликованное значение `cur_dev_s` в ней не используется. Пакеты с временем получения после `T` в признаки этой точки не включаются. При скорости дашборда 1× таблица признаков уже готова, а ML-инференс для новой точки вызывается по мере воспроизведения.

Фактическое время прибытия `time_fact_begin` запрещено как вход модели. В размеченном test оно читается отдельно только командой `mos_trans.stream_report` для оценки ошибки после прогноза.
