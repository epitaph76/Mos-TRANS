# Текст для формы «Загрузка решения»

**Репозиторий:** https://github.com/epitaph76/Mos-TRANS/tree/master

**Описание:** Mos-TRANS — прототип диспетчерской системы раннего предупреждения о задержке наземного транспорта. По доступной к моменту прогноза исторической телеметрии и плановому расписанию она оценивает задержку на остановке с плановым временем прибытия через 10–15 минут и вероятность опоздания более чем на две минуты. Дашборд показывает транспорт на карте, уровень риска, целевую остановку, наблюдаемый паттерн движения и рекомендацию. Backend принимает исторический поток и бинарные NDTP-пакеты от эмулятора; ML-инференс работает отдельным сервисом. Сервисы упакованы в Docker Compose, API описано через OpenAPI. Для живых NDTP-устройств прогноз пока недоступен без привязки к расписанию.

**Модели:** CatBoost-регрессор прогнозирует изменение текущего отклонения и переводит его в задержку в секундах. Ансамбль CatBoost-классификаторов выдаёт вероятность события `target_delay_s > 120`. Обе модели используют общие признаки, построенные без пакетов с `event_time` или `receive_time` позднее момента прогноза. Фактическое время целевой остановки не используется как вход.

**Воспроизведение:** положить `dataset.zip` локально, указать `DATASET_HOST_PATH` в `.env`, выполнить `docker compose up --build`, открыть `http://localhost:8080`. При скорости 1× прогноз вызывается по мере воспроизведения; признаки архива подготовлены заранее. Эмулятор NDTP из отдельного образа подключается к TCP-порту 9201; его случайные координаты показываются без прогноза, если нет соответствующего расписания. CSV для Data Science — `artifacts/integrated_submission/submission.csv`.

**Качество и ограничения:** MAE регрессора на опубликованном test по конкурсным точкам — 55,90 секунды. Для вероятности задержки более 120 секунд групповой holdout по семействам ТС дал Brier 0,1334. В отдельной проверке потоковых прогнозов MAE регрессора — 78,36 секунды по пакетам; вероятность в этом режиме пока отдельно не оценена. Окно 10–15 минут относится к плановому прибытию, а не к измеренному моменту возникновения задержки. Исходные данные относятся к одному дню, а train/test/validate включают связанные траектории, поэтому качество на новом периоде ещё не измерено.
