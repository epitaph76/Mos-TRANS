Документация проекта

Система принимает телеметрию транспорта по NDTP, показывает положение ТС на маршрутах из датасета и предоставляет исторический прогноз задержек.

Поток NDTP

TCP-приёмник: мостранс.хелпи.рф:9201. После подключения терминал отправляет NPH_SGC_CONN_REQUEST, затем сообщения NPH_SND_REALTIME с навигационной ячейкой G6CellNav00. Формат соответствует эмулятору из архива датасета.

Полученный peerAddress сопоставляется с unit_id в validate/traffic.csv; по tr_id находятся остановки в validate/schedule_plan.csv. Координаты, скорость и направление берутся из пакета.

Диспетчерская

Карта показывает принятые за последние 120 секунд пакеты NDTP на маршрутах датасета. Для диагностики архива 6 января 2026 года доступен HTTP-метод /api/replay/snapshot.

Прогноз задержки непосредственно по новому NDTP-пакету пока не рассчитывается; в диспетчерской отображаются приём, положение и маршрут.

Открыть Swagger API

Проверка подачи данных

Из корня репозитория отправьте несколько настоящих GPS-записей из validate/traffic.csv. Скрипт выбирает записи ТС 131672 перед первой точкой прогноза и кодирует их в NDTP так же, как эмулятор:

python scripts/send_ndtp_sample.py --dataset data/dataset.zip --host 135.106.219.68 --port 9201 --vehicle 131672 --count 3

После отправки проверьте /api/health (счётчик ndtpFrames) и /api/live/snapshot (ТС 131672, координаты и остановки). В архиве метки времени относятся к январю 2026 года; для отображения свежести в прямом эфире используется время приёма кадра.

Формат и границы данных

  • NDTP: little-endian, заголовки NPL 15 байт и NPH 10 байт, CRC-16/Modbus.
  • Идентификатор терминала — unit_id, транспортного средства — tr_id. Для validate они сопоставляются однозначно.
  • Схема проверочных точек: sample_id, tr_id, T, target_stop_id, target_time_begin, cur_dev_s.
  • Для исторического прогноза используются только пакеты с event_time ≤ T и receive_time ≤ T.

Swagger содержит актуальные HTTP-маршруты backend. Приём NDTP работает по TCP и поэтому не вызывается через Swagger.
