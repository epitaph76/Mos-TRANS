Проверка за 5 минут

Подайте NDTP, проверьте приём и маршрут, затем откройте исторический прогноз и метрики.

Адрес и Punycode

Домен в браузере: мостранс.хелпи.рф. Для эмулятора, TCP-клиента и команд используйте его ASCII-запись: xn--80axeckfde.xn--e1agiq1a.xn--p1ai. Браузер обычно преобразует кириллицу сам.

NDTP: xn--80axeckfde.xn--e1agiq1a.xn--p1ai:9201 (TCP). HTTP API: https://xn--80axeckfde.xn--e1agiq1a.xn--p1ai/api (HTTPS). В targetHost эмулятора укажите только имя без https:// и без порта.

1. Подать поток эмулятором

  1. Из архива организаторов извлеките ndtp-telemetry-emulator.tar.
  2. Запустите Docker-образ и передайте конфиг ниже.
  3. В конфиге указан unitId=985940 и GPS-точка ТС 131672 из validate/traffic.csv. Координаты фиксированы, время пакета проставляет эмулятор.
docker load -i ndtp-telemetry-emulator.tar
docker run --rm -p 18080:18080 --name ndtp-emu ndtp-telemetry-emulator:1.0

Во втором терминале сохраните JSON как config.json и отправьте его в локальный API эмулятора:

{
  "targetHost": "xn--80axeckfde.xn--e1agiq1a.xn--p1ai",
  "targetPort": 9201,
  "units": [{
    "unitId": 985940, "intervalMs": 5000, "autoGenerate": false,
    "cells": [{
      "type": "G6CellNav00",
      "fields": {
        "longitude": 378576500, "latitude": 557392120,
        "extraDopBit5": true, "extraDopBit6": true,
        "extraDopBit7": true, "speedAvg": 9,
        "speedMax": 9, "course": 240, "altitude": 158
      }
    }]
  }]
}
curl -X POST http://localhost:18080/api/config \
  -H "Content-Type: application/json" --data-binary @config.json

Остановить отправку: POST /api/config с тем же хостом и портом, но "units": [].

2. Подать реальные записи из датасета

Альтернатива эмулятору: скрипт кодирует настоящие строки validate/traffic.csv в тот же NDTP-формат. Нужны репозиторий и архив датасета организаторов.

python scripts/send_ndtp_sample.py \
  --dataset data/dataset.zip \
  --host xn--80axeckfde.xn--e1agiq1a.xn--p1ai \
  --port 9201 --vehicle 131672 --count 3

Скрипт отправляет handshake и три GPS-пакета unit_id=985940. Их event_time — январь 2026 года; свежесть в живом интерфейсе считается от момента приёма.

Проверка приёма

  1. Откройте /api/health: ndtpFrames растёт, ndtpErrors=0. Handshake тоже входит в счётчик кадров.
  2. Откройте /api/live/snapshot: в vehicles ожидается id=131672, unitId=985940, координаты и nextStop.
  3. Откройте дашборд и вкладку NDTP: в мониторе и на карте видно ТС. Пакет остаётся видимым 120 секунд после получения.
Нажмите кнопку для проверки.

3. Прогнозы и алерты

Два режима: во вкладке NDTP видны новые пакеты и маршрут; прогноз задержки по ним пока не рассчитывается. Во вкладке История доступны прогнозы модели на данных 6 января 2026 года.

Откройте исторический дашборд на 13:53:20: шкала времени, воспроизведение, прогнозы и события. Выберите ТС на карте, чтобы увидеть риск, объяснение и остановки. JSON того же среза — /api/replay/snapshot?at=50000. estimateSeconds — прогноз задержки; probability — вероятность опоздания более 120 секунд.

Индикация риска: ниже 70% 70–89% от 90%. Это пороги интерфейса; автоматической отправки уведомлений нет.

Нажмите кнопку для примера из исторического датасета.
